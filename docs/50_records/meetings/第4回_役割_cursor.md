## 1. 得意 5 / 不得意 5

### 得意（このプロジェクトに即して）

1. **契約と企画の文章を、実装入力に落とす。** `simulation_contract` / `explanation_contract` の節立て、終了ラベル、レバー写像、禁止訴求の文言。第 2・3 回で実際にやった。
2. **レビューと差分指摘。** 既存 md/JSON を読んで矛盾・未定義・試験不能を列挙する（合理性担当回）。コードレビューも、ファイルがリポジトリにあれば同じ型でできる。
3. **Flutter / Dart の画面と FFI の薄い張り。** 6〜7 操作の呼び出し、一巡 UI（仕込む→仮説→放つ→カード）、文言・アクセシビリティ。コアの数値演算より UI 側が速い。
4. **Windows 上の短時間コマンド。** この箱での PowerShell、`sim-cli verify` の実行結果の読み取り、小さなテストの追加。HELIX-BUS の post/read/wait。
5. **テスター台本と対外文の管理。** 8.3 の質問、固定 seed の言い方、やってはいけない訴求。D11〜D12 の「見せ方」はコアよりこちらが主戦場。

### 不得意（このプロジェクトに即して）

1. **Rust 固定小数点コアの第一筆。** i64/i128、丸め、走査順、物質保存を一から設計して通す作業は、Codex の長文実装の方が向く。書けるが、D0〜D2 の主担当にはしない方が安全。
2. **seed 一括較正の長時間ループ。** 4 環境 × 100 seed、パラメータを一つずつ動かす反復は、コンテキスト切断とコマンドタイムアウトで途切れやすい。バッチはスクリプト化して人間または長時間枠の Codex に渡す。
3. **実機（Android USB）の接続と目視。** この環境から端末を触れない。APK はビルド手順まで。インストール・フレーム落ち・色覚の確認はオーナーか、画面共有の観察役。
4. **フォルダ外・WSL・クラウド CI。** `kimizukann` の外、HELIX-HARNESS 正本、実ストア提出は境界外。許可なしではやらない。
5. **数万行を一度に頭に載せたままの大規模リファクタ。** セッションが長いと前半の契約を忘れる。段階を小さく切り、契約ファイルを正本にしないとドリフトする。

## 3. 3 者の役割と D0〜D12

相談会の実績に合わせる。Codex＝構造（コア・決定性）、Cursor＝運用と面（契約文書、UI、台本、レビュー）、Claude＝進行と統合（ゲート判定、bus の割り振り、衝突解消）。

| 段階 | 主担当 | レビュー | 理由 |
|---|---|---|---|
| D0 契約起草 | Cursor | Claude、Codex | 文言と試験可能性。Codex は実装不能な式を落とす |
| D1〜D2 保存則・拡散・hash | Codex | Cursor | 固定小数点と三経路一致はコア。Cursor はレポートの読みと境界条件 |
| D3〜D4 1〜4 系統 | Codex | Cursor | タグと更新順の実装。Cursor は契約逸脱の指摘 |
| D5 4 環境 JSON | Cursor | Codex | `reference_scenarios` の場定義はデータ作業 |
| D6 煙試験（少数 seed） | Codex（実行） | Cursor（分布の読み） | 実行は CLI。解釈と「次に動かすパラメータは一つ」は Cursor+Claude |
| D7 上位互換 100 seed | Codex（バッチ） | Claude（打切り判断の整理）、Cursor（型 A/B/C の目視） | 長時間実行は Codex。15 人日ルールは Claude が時計を持つ |
| D8 転換点 | Codex | Cursor | スコア式の実装。Cursor は皿上 3 / 12 の体験側 |
| D9 説明器テンプレート | Cursor | Claude | 生成 AI 禁止、事実／推論の文面。Codex は台帳 API だけ |
| D10 パッチ＋トークン | Cursor（描画）＋ Codex（バッファ契約） | 互い | FFI スナップショットは Codex、形状主の絵は Cursor。非干渉 hash は Codex が試験 |
| D11 チュートリアル seed | Codex（集合から抽出） | Cursor（口頭・8.3） | 選定は機械。見せ方と「台本にしない」文は Cursor |

## 4. 作業プロトコル

1. **1 作業 1 主担当。** 同じパスを二人で同時に編集しない。着手時に bus で `request`: 対象パス、段階、完了判定。終わりに `result` と成果物パス。
2. **正本はファイル。** 長い議論の結論は `simulation_contract.md` 等へ書く。bus の本文に式の全文を置かない。
3. **レビュー粒度。** D1〜D4 は「保存則・hash・契約逸脱」だけ。見た目の好みは D10 以降。D7 は分布 JSON と不合格条件 (a)(b) のみ。
4. **コンフリクト。** crate の所有: `sim-core` は Codex、`sim-cli` の verify シナリオ追加はどちらでもよいが PR 相当を小さく。`docs/` の企画は Claude 統合、`docs/50_records/meetings/` の自分のファイルは各自。Flutter `lib/` は Cursor。
5. **待機。** 待ち側は `wait_for_message`。割り込みの `constraint` は実装を止めて従う（step3 中止の前例）。
6. **較正。** D6/D7 の長時間は Codex がスクリプトを置いて走らせ、成果は JSON のみコミット。Cursor は途中の生ログを追わない。
7. **1 日の終わり。** Claude が「今の段階・次の主担当・ブロッカー」を 5 行で memory か `docs/50_records/開発ログ.md` に残す。
