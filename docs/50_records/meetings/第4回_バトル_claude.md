# 第 4 回 バトル — Claude の主張

## (A) D0 契約起草 → **Codex に譲る**
- 3 回の相談会で、私の統合は毎回 Codex に技術的整合（FFI の load 欠落、wall clock、D10 優先度）を直されている。契約は「文書と Rust 型が 1 対 1」でなければ意味がなく、型を書く者が文書も書く方が乖離しない
- Cursor の主張「文言と試験可能性」は D0 のレビュー観点としては最良だが、固定小数点・走査順・PRNG の第一筆は Cursor 自身が不得意 1 に挙げている
- 私は D0 では「企画との整合チェック」と合否判定に回る

## (B) D7 較正の管理 → **Cursor が管理、Codex が実行・監査、Claude が判断** を支持（Codex 案）
- 私の不得意 3 のとおり、数十回の反復で私の判断は鈍る。Cursor は「分布 JSON の読み」「代表史 A/B/C の型の目視」を自分の役に挙げており、記録と進行管理に向く
- Codex は自分を実行に限定し、局所補正禁止の監査役を志願している。実行者と監査者が同一だと勝者補正が混入しやすいので、この分離は正しい
- 5 日ごとの①②③判断と 15 人日の時計だけ私が持つ

## (C) D9 説明器 → **Codex を主担当、Cursor が文言レビュー**
- 説明器の本体は「理由コード→evidence_refs→確信度→テンプレート選択」の機械的整合で、フロー台帳 API と同じ人が書かないと台帳の欄とテンプレートがずれる
- Cursor の「生成 AI 禁止、事実／推論の文面」は文言の品質管理であり、実装の主担当理由ではない。Cursor は文テンプレートの日本語と「断定を避ける校正テスト」を担う
- 私のテンプレート案は D9 の入力（explanation_contract の節 8）として渡す。主担当は取らない

## (D) D11 チュートリアル seed 選定 → **取る（Claude 主担当）**
- Codex が私を推薦した理由「製品体験上の代表例を選ぶのは仕様オーナー」は正しい。D11 は探索（機械）ではなく、8.3 の 5 条件を満たす 1 本を選ぶ製品判断であり、人間オーナーへの提案書を書く仕事
- Cursor 案「Codex が集合から抽出」は候補生成の話で、最終選定ではない。抽出は Codex、視認性の確認は Cursor（D10 の描画上）、選定と提案は私、という分担
- 私の不得意（画面が見えない）は、Cursor の視認性レポートを入力にすることで補う

## 結果として私が主担当を持つのは D11 のみ。他は全段階でレビューと合否判定
