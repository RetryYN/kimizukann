## 2. 常設チャネル（辺）— 誰と誰が直接やりとりするか
```
             ┌────────── 設計ペア ──────────┐
   kimi(起草) ◄────────────────────────► grok(攻撃)      基本設計・契約・AT: kimi が書き grok が壊し kimi が直す。2 往復で合意しなければ Claude へ
     │  ▲                                   │  ▲
 AT/DD│  │実装の痛み                    UI設計│  │app 実装
     ▼  │                                   ▼  │
   composer(実装) ◄──────────────────────► grok            app/**: grok が遷移・敵対列を書き composer が実装、grok がマージ
     │                                       
     │ [TERM] 用語・文言                       
     ▼                                       
   gemini ◄──── 全員 [merged] を受けて記録 ────── Codex(ルーター: 催促・CI・環境)
                                                  │
   Claude ◄── [escalate] のみ ── 全員          オーナー ◄── 日次要約 ── Claude
```

| 辺 | 内容 | メッセージ |
|---|---|---|
| **kimi ⇄ grok（設計ペア）** | 基本設計の全章・契約・AT は kimi 起草 → grok 敵対 → kimi 修正。Claude は最後にマージするだけ | `[BD-xx][review-request]` / `[review]` / `[re-request]` |
| **kimi → composer（AT/DD）** | kimi が受入テストを red で先に書き、DD を審査。composer は AT を通す | `[Dn-xxx][brief]`（kimi が出す）/ `[tests-ready]` |
| **composer → kimi（実装の痛み）** | 実装中に設計が曖昧・矛盾なら composer が kimi に直接問う。kimi が DD を直す | `[Dn-xxx][question]` |
| **grok ⇄ composer（UI ペア）** | grok が画面遷移・敵対列・受入ケースを書き、composer が app を実装、grok が審査・マージ | `[UI-xxx][brief]`（grok が出す） |
| **kimi ⇄ grok → Claude（バトル）** | 設計で 2 往復して合意しない論点は両者の主張を並べて Claude へ。Claude が決めて ADR に書く | `[BD-xx][escalate] A案=… B案=…` |
| **全員 → gemini（言葉）** | 新語・UI 文言・テスター向け文は gemini に依頼。gemini は glossary を更新し文言を返す | `[TERM][request]` |
| **全員 → gemini（記録）** | `[merged]` を受けて開発ログに 1 行、日次で PR 一覧を要約して Claude へ | `[merged]` → `[LOG]` |
| **全員 → Codex（環境）** | CI 失敗・ツール不在・GitHub 設定は Codex。Codex は判断せず手順で直す | `[ENV][request]` |
| **Codex → 全員（催促）** | 放置 PR の催促、マージ条件そろいの通知 | `[nudge]` / `[ready-to-merge]` |
| **Claude ⇄ オーナー** | 日次要約、判断依頼（要件・RFC・境界外） | — |

## 3. 回し方（1 カードの流れ、Claude 不在で完結する）
```
kimi: AT(red)+DD 審査 ──brief──► composer: 実装 ──review-request──► kimi(契約) & grok(敵対)
                                                  ◄──review────────┘
composer: 返信/修正 ──re-request──► 承認 ──► kimi: merge ──[merged]──► gemini: 記録、Codex: checks 更新
```
Claude が出るのは: 基本設計・契約・golden のマージ、`[escalate]`、要件/RFC のオーナー橋渡し、日次要約。
