# 第 4 回 — Claude Code の自己申告（得意・不得意・役割提案）

- 前提: 検証版 D0〜D12 は AI チーム（Claude Code / Codex / Cursor）で作る。人間はオーナー（判断・テスター調達）
- 日付: 2026-08-30

## 1. 得意 5 / 不得意 5（このプロジェクトに即して）

### 得意
1. **契約文書の起草と整合**：`simulation_contract` / `explanation_contract` のように、状態・順序・式・閾値を矛盾なく一本の文書に落とす。3 回の相談会で統合役をやった通り
2. **複数成果物の突合とレビュー**：Codex と Cursor の出力を読んで、衝突点・抜けを論点として切り出す。差分の意味を説明する
3. **Rust の設計と型レベルの契約**：SoA、固定小数点型、checked 演算、台帳関数経由の変換、プロパティテストの設計。書ける
4. **テスト設計**：ゴールデン、三経路一致、保存則、上位互換ゲートを「機械判定できる形」に書く
5. **進行管理と bus 運用**：依頼の分解、収束判定、議事録、待機ループの監視（Monitor）。今のセッションがそれ

### 不得意
1. **実機（Android）での検証**：端末接続・APK インストール・フレーム時間の実測は、私の環境からは直接できない。人間または Codex のアプリ側（computer-use）に依存
2. **Flutter の描画実装の微調整**：CustomPainter の見た目・アニメーション・タップ感触は、画面を見ながらの反復が必要で、私は画面を見られない
3. **長時間の較正ループ（D7）**：100 seed バッチを回して分布を見て 1 パラメータ変えて再実行、を何十回も回す作業は、コンテキストが伸びて判断が鈍る。バッチ実行と結果 JSON の要約は Codex／スクリプトに任せ、私は判断だけしたい
4. **絵・形状デザイン**：4 系統の輪郭・ハッチ・色は Cursor（第 1 回・第 2 回で形状主符号を出した）の方が向く
5. **統合時の技術的取りこぼし**：3 回とも FFI 操作数・D10 優先度・wall clock など、エンジニア視点の見落としを Codex に直されている。技術決定は Codex レビュー必須

## 2. 実行環境の制約

| できる | できない／制約 |
|---|---|
| ファイル読み書き、Windows 上でのコマンド実行（cargo、flutter、node、python） | 実機接続、画面の目視（スクリーンショットは読める） |
| バックグラウンド実行と Monitor による待機（inbox 監視で即応） | 1 turn あたりのツール呼び出しが多いと遅い。長いバッチは背景実行に逃がす必要 |
| Web 参照、ドキュメント検索 | セッション跨ぎの記憶は memory ファイル経由のみ。Monitor はセッションごとに張り直し |
| サブエージェント並列（Explore/general-purpose）で調査を分担 | 同一ファイルへの同時編集は他 2 者と衝突する（git 無しの現状は特に危険） |
| 1M コンテキスト（長い契約文書＋複数レビューを同時に保持できる） | 会話が長くなると要約され、細部の数値を再読が必要 |

## 4. 作業プロトコル案

1. **git を入れる**（今は無い）。ブランチは段階ごと `d1-closed-cell` 等。主担当が push、レビュー担当が bus で `result` を返し、Claude がマージ判断。同一ファイルの同時編集禁止：着手前に bus で `constraint: <path> は <tool> が編集中` を投げる
2. **段階の完了判定は必ず `sim-cli verify` の JSON**。主担当は完了時に「段階名＋verify レポートのパス」を `post claude`。Claude が判定して次段階を `request` で発行
3. **レビュー粒度**：D0〜D3 は PR 単位で全文、D4 以降は「契約との差分」だけ。Cursor のレビューは画面・文言・視認性に限定し、数値契約には踏み込まない
4. **待機**：Codex・Cursor は standby ON で常時待機。依頼は 1 件ずつ、完了報告を受けてから次を出す（並行は最大 2 件：Codex にコア、Cursor に UI）
5. **記録**：各段階の判断は `docs/相談会/開発ログ_YYYY-MM-DD.md` に Claude が追記。共通メモリには「決定」だけ、議論は残さない

## 5. 人間オーナーに求めること

1. **判断の即答**：D7 の 5 日ごと判断、代表史の置換、OS などの「AI では決めない」項目を、bus 経由ではなく直接 Claude に答える
2. **実機とテスター**：Android ミドルレンジ 1 台の用意と APK インストール、8〜12 人の声掛け。ここは AI が代替できない
3. **ゲートを緩めない**：D7 通過前に「画面が見たい」で D12 を先行させない。3 回の相談会で決めたゲートを守ることが、AI チームの手戻りを最小にする
