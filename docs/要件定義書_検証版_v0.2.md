# キミ図鑑 検証版 要件定義書 v0.1

- 版: 0.2（起草 Claude、2026-08-30。kimi 審査 SRS-001 の 19 件を反映）　状態: **オーナー sign-off 済み（2026-08-30「進んでみ」）**。変更は RFC 経由
- 対象: 検証版（製品企画 §8、検証版計画 v1.0）。ストア版の要求は含めない
- 正本の階層: 製品企画 v0.3 ＞ 統合案 v0.5・検証版計画 v1.0 ＞ **本書（要件）** ＞ 設計 ＞ 実装。下位は上位に矛盾してはならない。矛盾を見つけたら本書を直してから下位を直す
- 設計は **基本設計** と **詳細設計** の 2 段。基本設計（外部設計）= ドメインモデル・アーキテクチャ・契約（公開 IF・schema・FFI・事前事後条件。`simulation_contract.md` はここ）・数値/決定性モデル・画面遷移・性能予算と、それらの受入テスト設計（AT）。詳細設計（内部設計）= モジュール／アルゴリズム／境界値／エラー処理／ユニットテスト設計（UT・property・golden）。各段はテスト設計を含んで初めて完成とみなし、実装は詳細設計から逸脱しない
- 書式: 1 行 1 要求。`ID | 要求（主語・条件・振る舞い） | 出典 | 検証方法 | 段階 | 優先`。検証方法の無い要求は載せない
  - 検証方法の種類: **AT**=受入テスト（CI で機械判定）、**UT**=ユニット／property、**MEAS**=計測（ベンチ・実機）、**INSP**=検査（レビュー・チェックリスト）、**USER**=初見テスター
