# 開発プロセス案 v0.2（DDD 設計 × TDD × トレーサビリティ × カンバン）

作成: Claude（2026-08-30）。v0.1 ハーネス案（CI・機械ゲート）を下流に置き、その上流を定義する。
原則: **設計はテストとセットでしか存在しない**。テストの無い設計項目は「未設計」、設計 ID の無いテストは「根拠なし」として CI が落とす。

## 1. 成果物の連鎖（上流 → 下流）と ID
```
REQ  企画 v0.5 の条項            docs/00_product/第2回_統合案_v0.5.md      例 REQ-1.1
DOM  ドメインモデル（DDD）        docs/20_design/domain/*.md               例 DOM-Cell, DOM-Lineage
CON  契約（不変条件・順序・数値） docs/30_contracts/simulation_contract.md 例 CON-§4
AT   受入テスト（段階ゲート）     crates/sim-core/tests/gate_Dn.rs      例 AT-D2-03
DD   詳細設計（段階ごと）         docs/20_design/detail/Dn-*.md            例 DD-D2-diffuse
UT   ユニットテスト               各 crate 内 #[test]                   例 UT-fixed-remainder
IMPL 実装                         crates/**                              PR 単位
```
- **トレース行列** `docs/20_design/trace.md`：REQ → DOM → CON → AT → DD → UT の対応表。
- CI job `trace`：(a) すべての REQ に ≥1 AT、(b) すべての AT に REQ と CON の参照、(c) すべての DD に AT、が無ければ fail。ID はコメント／見出しから正規表現で拾う（`// AT-D2-03 <- REQ-1.1, CON-§2`）。
- 齟齬が出る場所は「文書間の翻訳」なので、翻訳の両端に同じ ID を置いて機械で突き合わせる。

## 2. DDD の適用（このプロジェクト固有）
### 2.1 境界づけられたコンテキスト
| コンテキスト | 責務 | 実体 | 他コンテキストとの境界 |
|---|---|---|---|
| **SimCore** | 決定論的な世界の更新 | `crates/sim-core`, `sim-types` | 公開 API は `SimCore::{new, step, state_hash, save, load, invariant_report}` のみ |
| **Calibration** | seed バッチ・manifest・上位互換試験 | `crates/sim-cli` batch, `docs/calib/**` | SimCore を呼ぶだけ、状態を持たない |
| **Presentation** | 描画・説明器・札 UI | Flutter `app/**` | FFI 越しに StateSnapshot を **読むだけ**（腐敗防止層 = FFI 型変換） |
| **Distribution** | APK・テスター配布・フィードバック | `docs/dist/**`, CI artifact | Presentation の成果物を受け取る |

### 2.2 ユビキタス言語（`docs/20_design/domain/glossary.md`）
用語は契約・コード・UI 文言で **同じ語**を使う。例: `nutrient / biomass / carcass / waste / energy / occupancy_peak / lineage / trait_vector / mechanism_tags / termination_label / inflow / tick / phase / stream / state_hash / manifest / 札 / 空き家`。新語は glossary に追加してから使う（PR で CI が未登録語を warning）。

### 2.3 集約と不変条件（SimCore）
| 集約 | ルート | 不変条件（＝CON と AT の種） |
|---|---|---|
| World | `WorldState` | tick 単調増加、grid 寸法不変、lineages id 昇順ユニーク |
| Cell | `CellState` | 全プール ≥ 0、energy ∈ [0,1]、occupancy_peak ∈ [0,1] |
| Ledger（値オブジェクト） | `ConversionRule` | Σ出力 + 余り = 入力、余りは remainder_to へ、捨てない |
| Rng | `RandomStream ×4` | 消費順は phase 固定、保存に含める |
| Termination | `TerminationRule` | 優先順固定、EveryTick / AtTimeLimit の判定時点固定 |
| Save | `SaveEnvelope` | schema_version・model_version・config_hash・prng_state・state_hash を含む |

### 2.4 ドメインイベント（説明器・ログの語彙）
`Intake, Starved, Died, Reproduced, Emitted, Vacated（空き家化）, Reoccupied, Terminated(label)`。イベントは phase 内で発行し、説明器（D9）はイベント列だけから文章を作る（状態を直接読まない）。

## 3. TDD の規則
1. **順序**: DOM/CON 更新 → AT（kimi）→ DD（writer）→ UT red → IMPL green → refactor。PR の commit 履歴に「テスト追加 commit が実装 commit より前」があることを CI が確認（`git log --diff-filter=A -- '**/tests/**' '**/*_test.rs'` の時刻比較）
2. **受入テストは writer と別人**（kimi）。writer は `tests/gate_*.rs` を編集不可（CODEOWNERS）
3. **テストの質を機械で担保**: ゲート自己試験（v0.1 §3.4）＋変化 assert
4. **golden**（seed→hash、seed→終了ラベル）は Claude 承認でのみ更新
5. UT は「1 不変条件 = 1 テスト」。テスト名に ID を含める（`at_d2_03_diffusion_symmetric`）

## 4. カンバン運用（1 日スプリント）
### 4.1 ボード（`docs/kanban.md`、bus-ctl で自動更新。GitHub Projects に移行可）
```
Backlog | 設計(DOM/DD) | テスト作成(AT) | 実装 | レビュー | ゲート(CI+Claude) | Done
```
- **WIP 制限**: 各エージェント 1 枚。Claude のゲート列は 2 枚まで
- カード = brief ID（`D2-diffuse-001`）。列移動は helix-bus のメッセージ種別に対応: `[brief]`=Backlog→設計、`[design]`=設計→テスト作成、`[tests]`=→実装、`[started]`、`[result]`=→レビュー、`[review]`=→ゲート、`[approve]`=Done

### 4.2 Definition of Ready（実装列に入る条件）
- DOM/CON に該当 ID がある
- AT が **red で** commit 済み（kimi）
- DD が書かれ、Claude が「契約と矛盾なし」と判定

### 4.3 Definition of Done
- CI 全 job green（クロス OS hash 一致含む）、AT green、ゲート自己試験 pass
- reviewer approve + Claude gate approve
- trace.md 更新、開発ログ自動追記、glossary に新語なし or 追加済み

### 4.4 セレモニー（すべて helix-bus 上で、Claude が進行）
| いつ | 何 | 参加 |
|---|---|---|
| 日次 開始 | プランニング: Backlog から DoR を満たすカードを引く（3〜5 枚） | Claude, Codex(ルーター) |
| 随時 | デイリー相当 = `bus-ctl sessions` の状態とカード列 | 自動 |
| 日次 終了 | レビュー: Done カードのデモ = CI report.json とゴールデン差分 | 全員 |
| 日次 終了 | レトロ: 「機械で拾えなかった齟齬」を 1 件以上挙げ、CI か AT に落とす | 全員 → Claude が反映 |
